# 对象变更订阅

`GET /api/v1/subscriptions/objects/{object_type}` 是需要认证的尽力而为实时通知接口，
不是持久事件日志。正常通知仅包含标识符；完整状态必须通过有权限检查的查询接口读取。

每个订阅者使用有界队列。队列溢出时，服务端丢弃该订阅者已不完整的积压通知，
发送命名 SSE 事件 `resync_required`，数据为 `{"reason":"subscriber_overflow"}`，
随后结束流。其他订阅者不受阻塞。客户端必须显式监听这个事件；
EventSource 的默认 `onmessage` 不会收到命名事件。

收到通知后应使缓存失效，先重新建立订阅，再读取当前状态快照，并处理或缓存查询
期间到达的通知，避免恢复期间的变更遗漏。如果再次溢出，需要重新执行恢复。
其他连接中断后也应重新同步：接口没有实现 Last-Event-ID 重放，自动重连本身
不能恢复遗漏通知。

Outbox 的 SSE 回执仅表示向 broker 派发，不是每个远端订阅者的确认。
本机制不承诺无损投递，也不能恢复每一个历史中间状态。
